# MouseRemap (Shizuku + ネイティブ)

Androidに接続したマウスのボタンを、左右クリックを含めて付け替えるアプリ。

## 仕組み
1. Shizukuのshell権限プロセスが、APKに同梱したネイティブのデーモン(`native/mouseremapd.c`)を起動する。
2. デーモンは物理マウスを `EVIOCGRAB` で占有し、`/dev/uinput` の仮想マウスへイベントを再送する。
   その途中でボタンのコードを付け替える(左右入れ替え、中ボタン→戻る、など)。
3. ボタンに「Androidの操作(ホーム/戻る/通知…)」を割り当てた場合は、押下時にコマンドを実行する。
4. 仮想マウスは元のマウスの能力(移動・ホイール・高分解能ホイール等)をコピーして作る。

### 右ボタン = コンテキストメニュー(長押しタップ)
右ボタンの初期設定は「コンテキストメニュー(長押しタップで表示)」。
右ボタンを押した位置に、タッチの長押し(`input touchscreen swipe x y x y <長押し時間>`)を送る。
マウスの長押しを無視するアプリでも、タッチの長押しならメニューが出る。

押した位置(カーソルの画面座標)は、次の順で調べる。
1. OSのカーソル位置API(IInputManager)。Android 16の後のQPR以降にしか無い。
2. 無い端末(Android 15など)では、アプリが画面全体を覆う透明なオーバーレイを一瞬だけ重ね、
   デーモンがカーソルを+1px動かして戻す。カーソルの下のオーバーレイにホバーが届くので、その座標を使う。
   オーバーレイ権限が必要(アプリ接続時にShizuku経由で自動付与する)。
   shell側からアプリへ通知するので、アプリのプロセスが生きている必要がある(常駐サービスで保つ。タスクから消さない)。
どちらも使えない場合は「マウス長押し」で代用する。どの方式かは状態欄の「長押しタップ」で分かる。

Chromeなど右クリックに元から対応するアプリでは「変更しない」のほうが自然。

デーモンが止まる/アプリでオフにする/Shizukuが止まると、カーネルが占有と仮想マウスを自動で解放するので、マウスは元に戻る。

## APKの入手(GitHub Actions)
1. このフォルダをGitHubにpushする(`main`ブランチ)。
2. Actions タブ → `Build APK` → Artifacts の `MouseRemap-apk`。
3. `v2.0` などのタグをpushするとReleasesにも添付される。

CIは (1) ボタン付け替えロジックの単体テスト (2) NDKでネイティブをビルド (3) Gradleで`assets/`ごとAPK化、の順に動く。
手元でテストだけ試すなら `gcc native/test_remap.c -o /tmp/t && /tmp/t`。
ローカルのAndroid Studioでビルドする場合は、先に `bash scripts/build-native.sh` を実行する。

署名鍵を固定したい場合は、Secretsに `KEYSTORE_BASE64`、`KEYSTORE_PASSWORD`、`KEY_ALIAS`、`KEY_PASSWORD` を登録する。
未登録ならdebug署名で、ビルドごとに署名が変わる(更新時はアンインストールが必要)。

## 使い方
1. Shizukuを起動し、本アプリで権限を許可する(再起動のたびにShizuku側の起動が必要)。
2. 各ボタンの割り当てを選び、「リマップを有効にする」をオンにする。
3. マウスが効かなくなったら、タッチ操作でアプリを開いてオフにする。

## オーバーレイ権限が許可されないとき
「オーバーレイ権限を許可(Shizuku経由)」を押すと、appops と pm grant の結果がダイアログに出る。
それでも「未許可」のままなら、「オーバーレイ権限の設定画面を開く」から手動で許可する
(設定 > アプリ > MouseRemap > 他のアプリの上に重ねて表示)。

## うまく動かないとき(状態欄のエラー)
- `uinput(/dev/uinput): Permission denied` … その端末ではshell権限から仮想デバイスを作れない。
- `EVIOCGRAB: ...` … 他のプロセスが占有している。
- `この端末のABI向けバイナリがありません` … ネイティブのビルドに失敗している(CIログを確認)。
